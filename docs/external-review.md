# 外部评审记录（2026-09-12）

> 第三方视角对本项目的整体评价。当时的项目状态：记忆运转（promote / MemoryDoc / 折叠桥接）已提交，17 spec 全绿。

## 总评

教学/研究性质的原型；工程纪律远超大多数同规模项目，真正值钱的是那几个设计概念——但离"能用"还有距离。

## 做得好的地方

- **架构分层干净**：`Doc → DocPlugin → DocHub → AgentLoop` 单向依赖，每层职责单一，像俄罗斯套娃，读代码几乎不用猜它想干嘛。
- **TDD 纪律到位**：18 个 commit 全带测试计数（如"17 spec / 157 runs / 493 assertions"），每次改动先红后绿，不是装样子。
- **"注释即契约"有新意**：让 AI 和代码共享一个稳定、可控的知识接口，比直接把整个代码库裸给模型读，工程上聪明得多。
- **概念设计有深度**："真/分/联/变/简"本体论、`supersedes` 取代链（修订不覆盖原件只标废弃）、记忆 `promote` 内化成真方法——是认真想过的问题，不是堆功能。
- **实证习惯好**：不止写模拟测试，还真接 Agnes/DeepSeek 实测跨会话记忆 3/3。

## 要泼的冷水

- **自杀式安全的隐患**：AI 有全权 `apply_code` + 文件写入。自己"长出新方法"很酷，但真放生产，一个越狱提示就能让它往代码里塞歪逻辑。`verify` 的沙箱目前挡不住恶意代码，只挡语法错。
- **单文件存储会崩**：`memory.yaml` 一张表长大到几万条时，每次改写全量 dump + 原子替换，性能会明显退化。
- **没有 CI / 静态检查**：全靠本地跑 `rake`。规模再大一点，回归会开始漏。
- **环境裸露**：`bundle` 都没装，跑测试靠裸 `ruby -Ilib`。不是坏事，但说明还没到"可复现交付"阶段。
- **文档与代码不同步**：`sprint-plan.md` 停在 Sprint 6，Sprint 7/8（记忆、运转）未登记；README 也没提 `promote`。架构在跑，文档在追。
- **单 Agent / 个人项目的边界**：没有多会话并发、没有权限体系，决定了它只能当"概念验证"，不是通用框架。

## 改进优先级

1. 加 CI（GitHub Actions 一行 rake）——成本最低收益最大
2. 把 `verify` 改成隔离进程 / 沙箱再放行代码落地
3. 记忆存储升到 SQLite 或按会话分片，避免单文件膨胀
4. 文档同步补上 Sprint 7/8

## 一句话

"一个人能写出来的很有想法的 Agent 原型"，概念和纪律值钱，但想上生产还得面对安全、规模、可复现这三座大山。

## 项目定位（项目方的回应）

反正是实验项目，**有新结论最重要**。考核标准是"产出了什么可复用的结论"，而不是"能否上生产"。

### 本项目目前已沉淀的关键实验结论

- **注释即契约**：AI 与代码共享知识接口的可行性（受控读写元数据，比裸读源码更稳更省）
- **记忆本体论五标准**：真/分/联/变/简 —— 认知状态（stated/confirmed/superseded）、取代链（supersedes）、折叠溯源（from）可让记忆既求真又可纠错
- **记忆最终运转成代码**：promote 把确证记忆内化成可跑方法，@doc 溯源 memory id —— 经验从"记事本"进化成"肌肉"
- **经验经 doc 血管传递**：每轮折叠出的 lesson 自动沉淀为 Knowledge @doc，进下一轮 —— 遗忘=重构且不丢结论
- **TDD 纪律可量化**：每个 commit 带测试计数，回归用变异验证固化为"先红后绿"的硬习惯
